# TRAINING_ALGORITHM.md

A year-agnostic loop for training a Battlecode bot with an AI agent. It is distilled from five practice
seasons (later seasons weighted higher) and the cross-year `ADVICE.md`. Season-specific numbers live in
`RULES.md`, `TRAINING_LOG.md` and the tools, never here.

## 0. Objective

Maximise **absolute strength against the external field**: the batch rating of the shipped build on the
simulated ladder, and its expected score against every ladder bot. Beating our own old builds is a
means, never the goal. Two instruments disagreeing is a finding to surface, not a verdict to pick.

## 1. Instruments (know what each can and cannot see)

| instrument | answers | blind to |
|---|---|---|
| **Mirror gate**: candidate vs incumbent snapshot, random map, random side, one fresh engine seed per cell shared by both builds, each cell also played incumbent-vs-incumbent on that seed (paired); only discordant pairs count. (2024: the seed was not shared, and identical code flipped 15-29% of cells.) | is this change better than what it replaces; does it regress | anything both builds share; anything only the field does |
| **Sparring archetypes**: our own one-trick bots that reproduce a tactic the field uses on us | does the change survive / exploit that tactic | everything else |
| **Ladder**: scrimmage blocks against the external field under contest rules, batch Bradley-Terry rating (Elo scale), each of our builds its own player | are we stronger; what does the field punish | map/side noise at small N |
| **Replay reader**: one game to text (per-round metrics, event window, one robot's life, board at a round, our log lines, bytecode, navigation stats) | why a single game went the way it did | anything statistical |

Rules: every instrument is run first on a case with a known answer. A mirror result never judges a
change aimed at the field; a single seeded game is a filter, never a verdict.

## 2. Phase 0 — before any strategy (day one)

1. Rules digest with engine provenance for every mechanic; one starter-bot game read for its ending.
2. Headless bare-JVM runner, parallel gauntlet, per-game fresh seed recorded, timeout per game, dud and
   exception detection, private class trees per run, refuse-rather-than-fallback guards.
3. Determinism check: same seed twice identical; different seed different.
4. Replay reader with the modes above; unit tests on synthetic replays.
5. Bot iteration 0: turn loop with bytecode monitor (overrun = round changed during the turn; near miss
   > 90%), per-robot RNG from the id, one relative tie-break helper, decision-point log tags, constants
   file, unit tests on pure logic. Snapshot tool.
6. External field: discover by scripted search, download, compile blind (logs to files, counts to
   stdout), select each repo's final bot by name, calibrate every bot with two games.
7. Charts and a status/handoff file regenerated by one post-block command.
8. **Identity control** on every tool path that produces verdicts (mirror gate, filler, delivery block, ablation):
   a byte-identical copy of the incumbent reads 0 discordant pairs. Re-run it whenever a tool changes.
9. **Basics battery** (symmetry or other exact inferences never wrong and decided in time, 0 overruns, 0 exceptions;
   movement, combat and economy vs a control, failing only beyond 2 SE) on every build and test block.

## 3. The loop

1. **Select** a target from the rotation in §4.
2. **Trace** the motivating replay with the reader before hypothesising; enumerate mechanisms that fit;
   check a second game against a different opponent.
3. **Pre-register** in the log: mechanism; decision counter (log tag) that proves it fired;
   reachability at observed values; trigger frequency across other recent games; price (what it
   displaces); which instrument decides; gate; falsifier; for numeric changes a dose ladder with a
   byte-identical zero arm.
4. **Implement** one change. Tests pass (including a dead-code check and a switch-intent check). Zero overruns in a
   logged game; the basics battery holds.
5. **Diagnose — no shortcuts** (owner, PROMPTS 66-67): (a) one logged game where the mechanism can fire, read
   against the incumbent on the same seed; then (b) a delivery mini-block (`tools/delivery-gate.sh`, ~24 random band
   cells) showing the arm produces the pre-registered behaviour: the mechanism fires in >= 90% of games and the
   signature reaches its target (for a copied tactic, >= 50% of the gap to the opponents'). No band test, mirror gate
   or ladder block starts until (b) passes; `tools/band-test.sh` refuses without the PASS file. A failed delivery is
   fixed and re-diagnosed, or the arm is dropped and logged as not delivered; it is never judged on wins. Guards
   (`nw:`) protect against harm the band test would not see; there is **no kills guard** (owner, PROMPTS 183): a
   mechanism that trades bodies for flags or crumbs is judged by the band test, not stopped at delivery.
6. **Gate** (§5). ACCEPT, REJECT, or PROVISIONAL.
7. **On accept**: snapshot; archetype regression; ladder block(s) as a submission; post-block
   (record, refit, charts, study); update TACTICS, ledger, handoff; commit explicit paths; push.
8. **On reject**: restore `src/bot` from the incumbent snapshot byte-for-byte; ledger entry with the
   number that closed it and a re-open condition.

## 4. What to work on (rotation)

Sources, used in turn so none dries up:
- **Defects in our own games** (no opponent needed): idle units, stuck or oscillating movement,
  resources floating, overruns, exceptions, shut-off gates. Repairs transfer; reallocations rarely do.
- **Tactics the field beats us with** (`TACTICS.md`): adopt the tactic first and submit it, then neutralize
  it, tested against our own adopted copy.
- **Block census**: earliest-onset metric that separates wins from losses, stratified by opponent.
- **Capability gap**: unused API methods, unused mechanics, cross-year principles.
- **Tactic levels** (research/TACTIC_LEVELS.md, TL-1): a copied tactic is armed only if it is elementary, or if its
  below-par root capability is already at par; every arm first passes a delivery mini-block (~20 cells: the mechanism
  fires in >= 90% of games and our signature closes >= 50% of the gap to the opponents'). Otherwise build the root
  capabilities first, each gated on its own early metric measured against a same-block control.

Balance: after 3 consecutive rejects in one functional area, leave it. At least one structural swing
in every 4 attempts, and immediately when the ladder is flat for 5 accepts. Plateau escalation, in
order: **correctness audit of the bot and the measurement pipeline** (`AUDIT_PROMPT.md`, full procedure in
`AUDIT_PLAYBOOK.md`; also whenever a basic is found broken: in 2024 it ended a 50-experiment plateau, +33 of 234 seed
pairs); ablate accepted features; API/engine sweep; re-read field games; re-read `ADVICE.md` and other
years; jointly necessary pairs; structural attempt; rewrite (keep the plumbing, change the roles).
Never idle: while a gate runs, read replays and prepare the next candidate.

## 5. Gates and statistics

- **Mirror screen** (every candidate): paired cells on random maps and sides; SPRT on discordant pairs
  (H0 0.50, H1 0.58, α = β = 0.05, batches of 16); at the cap read the discordant pairs by sign test:
  p < 0.01 with >= 12 discordant decides; p < 0.10 for the candidate = provisional (stack the next
  candidate on it, test the stack against the incumbent). A candidate with an overrun or new
  exceptions is void, not rejected.
- **Field judge** (changes aimed at the field, and any accept that the mirror calls marginal): the
  candidate is submitted as its own ladder player in blocks alternating with control blocks of the
  incumbent in the same period against the same band; accept when the pooled difference's lower
  one-SE bound is above zero after a confirming second pair of blocks. Never compare against the
  incumbent's pooled history (winner's curse).
- **Archetype arm** (neutralizations): pre-register a second arm against the archetype that has the property,
  decided before the gate runs.
- Never read a running batch. Never move a bar after seeing a number. Diff game by game and read the
  shape (one-directional on one map or side = real; scattered = noise). Report maps swept from both
  sides. Measure the noise floor with an inert change once per lineage.

## 6. The ladder (simulating online scrimmages)

- Ladder games against external bots are scrimmages: random map from the corpus, random side, fresh seed,
  rotating opponents; external bots never play each other. Diagnostics may choose maps and sides against an
  external bot (PROMPTS 178); those games never enter the ladder or a pre-registered victory read.
- Pool = the band: the bots rated nearest the playing build, above and below. Never-played bots are
  placed by a two-game calibration block.
- Rating = batch Bradley-Terry over all our games, weak prior, repeated (pair, map, seed) cells counted
  once. Grade = rating ± 95% interval, rank, expected field score, score vs bots rated above.
- Withdraw a submission whose interval falls below the previous submission's rating.
- External source is never read. Their games may be watched and their tactics recorded in TACTICS.

## 7. Records

- `TRAINING_LOG.md`: append-only, one entry per attempt (target, trace, pre-registration, counters,
  gate numbers, decision, lesson, next); closed-directions ledger and functional-area map at the end.
- `TACTICS.md`: per opponent tactic: evidence, Adoption progress, Neutralization progress.
- `LEARNINGS.md`: durable lessons, each with its measurement.
- `HANDOFF.md`: state block first (incumbent, grade, in-flight run ids), then gotchas.
- `PROMPTS.md`: every owner prompt verbatim. Charts regenerated at every block; nothing stale stays.
- Commit explicit paths; push after every commit.

## 8. Hyperparameters

| name | value |
|---|---|
| SPRT p0 / p1 / α / β / batch / cap | 0.50 / 0.58 / 0.05 / 0.05 / 16 / 320 pairs |
| ladder block / band half-width | 48 games / 8 bots |
| max consecutive rejects per area | 3 |
| structural swing | >= 1 in 4 attempts |
| bytecode near-miss | 90% of limit; overruns must be 0 |
| concurrent games | cores − 1 on the compute machine; 1 on the session machine |
